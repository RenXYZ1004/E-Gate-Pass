# SISC e-Gatepass — SEO and Public Website Audit

## Implemented in source

| Requested item | Result | Notes |
|---|---|---|
| Server-side rendering (SSR) | **Skipped intentionally** | The site is a small, multi-page HTML/JavaScript application. The public pages already have crawlable HTML; build-time SEO metadata is now rendered into the deployed output. Converting the faculty system to an SSR framework would be a high-risk rewrite with little SEO value for a school operations dashboard. |
| `robots.txt` | **Added by build** | Allows public pages to be crawled, blocks `/api/`, and points to the generated sitemap. |
| `sitemap.xml` | **Added by build** | Lists only `/`, `/privacy-policy`, and `/terms-of-service`; it excludes the dashboard and student/temporary-pass forms. Uses absolute production URLs. |
| Unique title tags | **Added/standardized** | Landing page, faculty dashboard, permanent form, temporary form, privacy policy, terms, and 404 page have distinct titles. |
| Meta descriptions | **Added/updated** | Each page now has a page-specific description. |
| One H1 per page | **Applied where appropriate** | Landing, forms, policy, terms, and 404 each have one H1. `app.html` is an authenticated operational shell with no static H1 and is explicitly `noindex`; its visible page headings are generated by the app. |
| Canonical tags | **Added for indexable pages** | Landing page, privacy policy, and terms use self-referencing absolute canonical URLs generated from the production domain. No canonical is added to pages marked `noindex`. |
| Open Graph image | **Added** | New 1200 × 630 `og-image.jpg`, with Open Graph and Twitter card metadata on indexable pages. |
| Custom 404 | **Added** | Branded `404.html` with links back to the home page and public forms. |
| 301 redirects | **Skipped as duplicate/unnecessary** | `cleanUrls: true` and `trailingSlash: false` already normalize `.html` and trailing-slash URLs on Vercel; Vercel uses a permanent 308 for `.html` clean-URL redirects. No retired legacy paths were provided, so invented 301 mappings were not added. |
| Alt text | **Improved** | Public logos and sample-pass images have descriptive alternatives; profile-photo templates with a known name now include alt text. |
| WebP images | **Added with fallbacks** | Generated WebP versions of both logos and sample-pass artwork. Sample cards use `<picture>` with WebP first and PNG fallback; original PNGs remain for compatibility, manifests, and mail templates. |
| Lazy loading | **Added/retained** | Below-the-fold sample cards and selected profile photo previews use lazy loading and async decoding. The logo in the main hero remains eager to avoid delaying the brand. |
| Organization schema | **Added** | JSON-LD `EducationalOrganization` and `WebSite` graph on the public home page. |
| Breadcrumbs | **Added** | Visible breadcrumbs and `BreadcrumbList` JSON-LD on public legal pages. Operational forms remain noindex and retain their existing return-to-home controls. |
| Internal links | **Added/improved** | Footer/contact links point to the contact section, privacy policy, and terms. Legal pages link back to the home page. |
| Google Analytics | **Integration ready; off by default** | Only the public home page supports GA4. When a valid `GA_MEASUREMENT_ID` is configured, an explicit consent choice is required before analytics loads. No GA script runs on the dashboard or gate-pass forms. No real Measurement ID was supplied, so tracking is not active in this package. |
| Search Console | **Verification hook added; not verified** | Set `GOOGLE_SITE_VERIFICATION` to the exact HTML-tag token issued by Search Console, deploy, then click Verify in Search Console. DNS verification is an alternative and does not use this meta tag. |
| Privacy policy | **Updated** | Explains general contact-form data handling and optional consent-based analytics. The school’s privacy officer/DPO should review the policy before production. |
| Working contact form | **Implemented; email requires configuration** | Public form posts to `/api/contact`, validates server-side, escapes email HTML, includes a honeypot and a low per-instance rate limit, and sends via the existing Gmail OAuth setup. Delivery requires valid `GMAIL_*` environment variables and `CONTACT_TO_EMAIL` in Vercel. |

## Deployment requirements

1. Set `SITE_URL` in Vercel to the real production origin (for example `https://your-real-domain.edu`). If omitted, the build attempts to use Vercel's `VERCEL_PROJECT_PRODUCTION_URL` / `VERCEL_URL` system variables. If those variables are not exposed, the build stops instead of publishing fake canonical URLs.
2. Set `CONTACT_TO_EMAIL` to the approved school mailbox, and confirm all four Gmail OAuth variables (`GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN`, `GMAIL_USER_EMAIL`) are valid. Then submit a real contact-form test and confirm receipt.
3. In Google Analytics, create a web data stream and copy its Measurement ID (starts with `G-`). Set `GA_MEASUREMENT_ID` only after the school approves the use and policy wording. Analytics stays off when the variable is empty.
4. In Google Search Console, choose HTML-tag verification and set its token as `GOOGLE_SITE_VERIFICATION`, or use DNS verification. Submit `https://YOUR_REAL_DOMAIN/sitemap.xml` after deployment. Search Console cannot be verified automatically from this source package because it requires access to the school's Google account/domain.
5. The public pages and forms are not to be mistaken for backend access control. This SEO change does not resolve the previously documented Apps Script authorization concern.

## Automated checks run

- `npm run check:syntax` — parses JavaScript sources and inline scripts (including API handlers and Apps Script).
- `npm run check:seo` — checks page titles, descriptions, H1/noindex policy, canonical and OG metadata, WebP files, organization schema, and contact form assets.
- `node build-seo.cjs` with test values for `SITE_URL`, `GA_MEASUREMENT_ID`, and `GOOGLE_SITE_VERIFICATION` — generated `dist/`, `robots.txt`, and `sitemap.xml`, and confirmed placeholder replacement.
- A production deployment, live Search Console verification, real Analytics consent collection, and actual Gmail delivery still require the school's Vercel/Google credentials and were not claimed as tested.
